## Complete revision report

{report_transport_instructions} Copy these controller binding fields exactly:
{report_binding}

Add these required fields:
- `published_head`: full 40-character head actually published by this run, or
  the unchanged pinned head when nothing was pushed. Record partial pushes too.
- `outcome`: exactly FIXES_PUSHED_RECHECK_NEEDED, NO_CHANGES_RECHECK_NEEDED, or
  NEEDS_HUMAN_DECISION. This dedicated field alone selects the outcome; prose
  may quote these tokens freely.
- `revision_summary`: resulting behavior and scope. The controller displays
  pinned and published heads above it.
- `findings`: an array with exactly one object per complete pinned reference.
  Each object has `reference`, `disposition`, `assessment`, `evidence`, and
  `change`. All are non-empty strings. Disposition is `repair`, `replacement`,
  `no-change`, or `unresolved`. `change` describes the actual change or concrete
  reason for no change. For a replacement, explain the new contract, tradeoff,
  rejected approach and affected surfaces. Do not omit unresolved findings.
- `verification`: commands/probes actually run and results, regression coverage,
  and relevant checks not run with reasons. Include applicable proof evidence.
- `verification_status`: `passed`, `failed`, or `unavailable`. Use `passed` only
  when every required check passed; waivers do not invent passing checks.
- `verification_waiver`: empty string unless the configuration below requires
  the exact value VERIFICATION_UNCONFIGURED_WAIVER.
- `documentation`: PR/documentation updates, or an explicit statement that none
  are needed.
- `remaining_work`: unresolved work and follow-up owner/reference, or none.
- `additional_context`: optional free-form explanation, empty or omitted when
  unnecessary. Extra discussion never adds required finding identities.

Prose strings permit paragraphs, lists, fenced code and useful subsections;
encode newlines as JSON string escapes. There is no four-line prose grammar or
minimum report length. Keep all authored text within {summary_budget}
characters AND UTF-8 bytes. The single complete rendered comment is limited to
60,000 characters AND bytes including controller metadata. Oversize or malformed
reports retain complete evidence and take a human hold; they are not truncated,
split into comments, or sent to another implementation run to repair prose.

Choose FIXES_PUSHED_RECHECK_NEEDED only after all findings have repair,
replacement or no-change dispositions, at least one repair/replacement exists,
every required verification command passes, and the push succeeds. Choose
NO_CHANGES_RECHECK_NEEDED only when every finding has an evidence-backed
no-change disposition, verification passes, and the pinned head is unchanged.
Both outcomes request re-review at ai:revised. If any finding remains unresolved,
verification fails or cannot run, required authority is unavailable, or work is
blocked, choose NEEDS_HUMAN_DECISION and include the complete explanation,
including any partial pushed work. Field presence does not certify correctness.
